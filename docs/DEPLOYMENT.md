# Deploying Nigran 360

Free-tier topology (no paid services):

| Part | Host | Notes |
|---|---|---|
| Database | Hosted Microsoft SQL Server (e.g. MonsterASP.net free MSSQL database) | Remote access on port 1433. Schema is created automatically by the API's migrations on first connect. |
| API | Render free web service (Docker, `Dockerfile.api`, `render.yaml`) | Uses ODBC Driver 18 with encryption. Free instances sleep after ~15 minutes idle; the first request after that takes up to a minute. |
| Frontend | Netlify or Vercel (static SPA from `frontend/`) | `netlify.toml` / `vercel.json` rewrite every route to `_shell.html`. |

The camera/microphone AI engine (`run_proctor_engine.py`) needs a local machine and is not deployed. Browser-side monitoring (tab switches, copy/paste, fullscreen, ID/room photos) works in the cloud.

## 1. Database
1. Create a free MSSQL database at your SQL Server host.
2. Note the server host name, database name, login and password. Keep the password out of Git and chat.

## 2. API on Render
1. Render dashboard → **New** → **Blueprint** → connect `ebbad-dev/Nigraan360` (branch `main`). Render reads `render.yaml`.
2. Fill the prompted environment variables:
   - `PROCTORAI_DB_SERVER` = host name (add `,1433` if the host requires an explicit port)
   - `PROCTORAI_DB_NAME`, `PROCTORAI_DB_USER`, `PROCTORAI_DB_PASSWORD`
   - `PROCTORAI_BOOTSTRAP_ADMIN_EMAIL` / `PROCTORAI_BOOTSTRAP_ADMIN_PASSWORD` = first administrator (created only when the database has no admin)
   - `CORS_ORIGINS` and `FRONTEND_URL` = the frontend URL from step 3 (update after the frontend exists)
   - `AUTH_SECRET` is generated by Render.
3. Deploy, then open `https://<service>.onrender.com/health` → `{"status":"healthy",...}`.

## 3. Frontend on Netlify (or Vercel)
- Netlify: **Add new site** → import the repo → **Base directory** `frontend` (build settings come from `netlify.toml`).
- Vercel: **Add New Project** → import the repo → **Root Directory** `frontend` (settings from `vercel.json`).
- Environment variable: `VITE_API_BASE_URL` = `https://<service>.onrender.com`.
- Deploy, then set the frontend URL in Render's `CORS_ORIGINS`/`FRONTEND_URL` and redeploy the API.

## 4. Smoke test
- `GET <api>/health` returns healthy.
- Sign in on the frontend with the bootstrap administrator.
- Create demo accounts/data (see README "Demo data").

## Step-by-step checklist (finish before the 20:00 PKT cutoff)

Budget about 45 minutes; the Render Docker build alone takes 10–15 minutes.

1. **Database (MonsterASP or any hosted MSSQL)**
   - Create the free MSSQL database. Note: server host, database name, login, password.
   - Make sure remote access is enabled (port 1433).
2. **API (Render)**
   - Render → New → Blueprint → repo `ebbad-dev/Nigraan360`, branch `main`.
   - Set the prompted variables (names only; type the values in Render, never in Git or chat):

     | Variable | Value |
     |---|---|
     | `PROCTORAI_DB_SERVER` | DB host (append `,1433` if required) |
     | `PROCTORAI_DB_NAME` | DB name |
     | `PROCTORAI_DB_USER` / `PROCTORAI_DB_PASSWORD` | DB login |
     | `PROCTORAI_BOOTSTRAP_ADMIN_EMAIL` / `PROCTORAI_BOOTSTRAP_ADMIN_PASSWORD` | first admin (optional if you run the seed in step 4) |
     | `CORS_ORIGINS` | `https://<your-site>.netlify.app` (set a placeholder now, fix in step 5) |
     | `FRONTEND_URL` | same frontend URL (used in PDF verification links) |

   - `AUTH_SECRET` is generated by Render. Wait for the deploy, then open `https://<service>.onrender.com/health`. It should return `{"status":"healthy"}`. Tables are created automatically on first connect.
3. **Frontend (Netlify)**
   - Add new site → import repo → **Base directory** `frontend` (build command and publish dir come from `netlify.toml`).
   - Environment variable `VITE_API_BASE_URL` = `https://<service>.onrender.com` (no trailing slash). Deploy.
4. **Seed demo data into the hosted database** (from this machine, PowerShell, repo root):
   ```powershell
   $env:PROCTORAI_DB_SERVER="<host>"; $env:PROCTORAI_DB_NAME="<db>"
   $env:PROCTORAI_DB_USER="<login>"; $env:PROCTORAI_DB_PASSWORD="<password>"
   $env:PROCTORAI_DB_TRUSTED="false"; $env:PROCTORAI_DB_ENCRYPT="true"
   .venv\Scripts\python scripts\seed_demo.py
   ```
   This creates the demo accounts listed in the README and the published `DEMO360` exam.
5. **Finish CORS**: in Render set `CORS_ORIGINS` and `FRONTEND_URL` to the real Netlify URL, then wait for the redeploy.
6. **Smoke test on the deployed site**
   - Sign in as `examiner@nigran360.demo` and check the `DEMO360` exam.
   - Sign in as `candidate@nigran360.demo` and start the exam.
   - DevTools → Network → Offline, answer a question, and check that it shows "Pending sync". Go back online and check that it shows "Saved on server".
7. Put the two URLs in the README "Live deployment" section **before 20:00 PKT**. Make no commits or deploys after the cutoff.

Free Render instances sleep after about 15 idle minutes. Open `/health` a minute before the demo so the API is awake.
